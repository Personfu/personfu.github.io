Static disassembly of the unchanged archive executable:
  00648670  0F C5 C4 00   pextrw eax,mm4,0
  00648674  C1 E8 08      shr eax,8
  00648677  0F 6F BC C6 00 08 00 00
                         movq mm7,[esi+eax*8+800h]

PEXTRW extracts a 16-bit word into a 32-bit register with zero extension.
Therefore the following logical shift must produce a value in 0..255.
The observed 00FFFF80 is incompatible with correct zero extension. It is
exactly the result of sign-extending word 8000h to FFFF8000h then shifting
right eight. The effective address matches the observed fault exactly:
  0071B800 + (00FFFF80 * 8) + 800 = 0871BC00
Correct extraction would produce index 80h and address 0071C400.
The surrounding routine uses three tables spaced 800h bytes apart, packed
MMX adds, arithmetic shifts and unsigned byte packing to produce two RGB
output rows. Its structure is a YUV-to-RGB conversion routine; this role is
an inference from the code, not a recovered symbol name.

Subsequent exception processing calls game handlers 0065E502, 005FBF08,
then 00E5BF08. Handler 00E5BF08 faults at 00E5BF0F (an IN instruction),
producing recursive C0000096 EXCEPTION_PRIV_INSTRUCTION handling. These
secondary faults must not replace 00648677 as the first useful game fault.
Earlier 002c syscall C0000005 and 00dc RPC 6BA events occurred before the
main game loaded and were handled; they are separate from this fault.

Confirmed emulator source defect
--------------------------------
Build 96 source revision: f96673d8c9bb5150422521c5a625f9278e405925
common_pextrwR32Mmx assigns the return of simde_mm_extract_pi16 directly
to cpu->reg[r1].u32. The bundled SIMDe function returns int16_t. C++
conversion of a negative int16_t to U32 preserves the sign through integer
promotion, producing FFFFxxxx rather than the required 0000xxxx.

Primary sources at the exact runtime revision:
https://github.com/danoon2/Boxedwine/blob/f96673d8c9bb5150422521c5a625f9278e405925/source/emulation/cpu/common/common_sse.cpp
https://github.com/danoon2/Boxedwine/blob/f96673d8c9bb5150422521c5a625f9278e405925/lib/simde/simde/x86/sse.h

The optimized Wasm JIT pextrwRegMmx emits I16X8_EXTRACT_LANE_U, which is
unsigned. Interpreter execution and JIT warmup/fallback still use the signed
common helper, so a JIT runtime can encounter this defect before compiling
the relevant block. This also explains why a generic D3D9 triangle can pass
while this original-game conversion path fails.
https://github.com/danoon2/Boxedwine/blob/f96673d8c9bb5150422521c5a625f9278e405925/source/emulation/cpu/wasm/jitWasmCodeGen.cpp

The durable emulator fix is an explicit U16 conversion before the U32
assignment, with signed-bit test coverage (8000h, FFFFh, all four lanes,
all eight destination registers). It requires rebuilding the runtime.
