RFC / standards excerpts (paraphrased)

RFC 7515 sec. 8 (JWS Unsecured)

"none" indicates an unsecured JWS. Implementations that verify a signature MUST reject "none" as an algorithm by default. The Tier-4 SW does not. That is the lesson.

RFC 8725 sec. 3.1 (JWT BCP)

Algorithm confusion: a verifier that does not bind the public key to the expected algorithm can be tricked into using an RSA public key as an HMAC secret. The Tier-5 SW does this on /api/v1/internal/super.

RFC 9110 sec. 5 (HTTP semantics)

Request and response headers are advisory; trust in them must be earned by upstream context. X-Forwarded-For is set by intermediaries; trusting the first hop is the F27 mistake.

RFC 6797 (HSTS)

Strict-Transport-Security pins TLS-only access. CSP upgrade-insecure-requests is the per-document analog; both ship on this page.
